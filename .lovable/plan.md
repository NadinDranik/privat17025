## Поиск внутри темы чата

Добавить в шапку чата (`src/routes/_authenticated/chats.$chatId.tsx`) кнопку-иконку поиска, которая раскрывает поле ввода. По мере ввода фильтруются сообщения текущего чата.

### Что ищем
- По тексту сообщения (`messages.body`, регистронезависимо, подстрока).
- По имени файла во вложениях (`message_attachments.name`, подстрока).

### Поведение UI
- Иконка «лупа» рядом с заголовком в `header`.
- Клик — показывается `Input` с автофокусом и кнопкой закрытия (Esc / крестик очищает запрос).
- Когда запрос непустой:
  - Список сообщений в основной области заменяется на отфильтрованный (только совпавшие сообщения, в исходном порядке).
  - Над списком — строка «Найдено N» и кнопка «Очистить».
  - В каждом совпавшем сообщении подсвечиваем найденные фрагменты в тексте (обёртка `<mark>` с токенами темы) и в названии файла.
  - Если ничего не найдено — «Ничего не найдено».
- Пустой запрос — обычный режим чата (всё как сейчас, включая автоскролл вниз).
- Автоскролл вниз отключается в режиме поиска.

### Технические детали
- Фильтрация на клиенте по уже загруженным `messages` (до 500 — текущий лимит). Бэкенд/SQL не трогаем.
- Локальный стейт `search: string` и `searchOpen: boolean`.
- Хелпер `highlight(text, query)` — режет строку и оборачивает совпадения в `<mark class="bg-primary/30 text-foreground rounded px-0.5">`.
- Совпадение по сообщению: `body` содержит запрос ИЛИ хотя бы одно `attachment.name` содержит запрос.
- Скрываем поле ввода нового сообщения? — оставляем как есть (поиск не блокирует отправку).

### Ограничение
- Ищем только в пределах последних 500 загруженных сообщений (текущий лимит загрузки). Если потребуется глубокий поиск по всей истории — это уже отдельная задача (server-side SQL + ilike), сейчас не делаем.
