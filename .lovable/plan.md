## Проблема

`/chats/3c2bb83b...` открывается пустым: маршрут совпадает, но ничего не видно.

Причина: в TanStack Router dot-routing файл `src/routes/_authenticated/chats.tsx` становится родительским layout-ом для дочернего `chats.$chatId.tsx`. У layout-родителя должен быть `<Outlet />`, иначе дочерний роут «матчится», но рендерить его некуда. Сейчас `chats.tsx` — это полноценная страница со списком, без `<Outlet />`.

## Решение

Разделить роли: сделать `/chats` обычным leaf-роутом (без детей), а `/chats/:chatId` — самостоятельным sibling-роутом.

### Шаги

1. Переименовать `src/routes/_authenticated/chats.tsx` → `src/routes/_authenticated/chats.index.tsx`.
   - URL остаётся `/chats`.
   - Файл больше не является layout-родителем для `chats.$chatId.tsx` — оба роута становятся независимыми листьями под `_authenticated`.
   - Содержимое и `createFileRoute("/_authenticated/chats/")` (или TanStack сам сгенерит `/chats` через index) — оставить как есть, только обновить путь в `createFileRoute` если потребуется (`"/_authenticated/chats/"`).
2. Файл `chats.$chatId.tsx` не трогаем — он уже самостоятельно рендерит полный экран чата с сообщениями, вложениями (фото/видео/файлы до 20 МБ), realtime, удалением и формой отправки.
3. `routeTree.gen.ts` перегенерируется автоматически.

### Что в итоге заработает

- `/chats` — список чатов (как сейчас).
- `/chats/:chatId` — экран чата: история сообщений, отправка текста, прикрепление фото/видео/файлов через Paperclip, Ctrl/⌘+Enter для отправки, realtime-обновления, удаление своих сообщений (и любых — для админа).

### Проверка

После сборки открыть `/chats/3c2bb83b-718f-4e77-b4d4-db795fcd8dc7` — должен отрисоваться чат с шапкой «п. … / название», лентой сообщений и формой ввода внизу.
